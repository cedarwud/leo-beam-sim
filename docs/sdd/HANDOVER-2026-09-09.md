## 改渲染邏輯時的工作流

**1. 找決策的擁有者**
```bash
npm run audit:appearance-cost                 # 15 個決策,各自的擁有檔
npm run audit:appearance-cost -- --decision <id>
```
manifest 用 owner 的口吻寫,拿你的一句話去對。**找不到 = 那個決策沒登記,先登記再改。**

**2. 算出改動的效果(不要開瀏覽器)**
```bash
npm run audit:render-timeline -- --at 88      # 那一秒畫面上每個 item
npm run audit:render-timeline -- --diff 6,7   # 跨過一次真的 intra 換手
npm run audit:render-timeline -- --at 74      # 落在一次真的 inter 換手
npm run audit:render-timeline -- --events 0..600 --only-discrete
```
確定性、無瀏覽器、印出每個錐體/標記/軌跡的顏色、透明度、幾何、以及**哪一階 ladder 贏了**。

**3. 改完驗證**
重構(不該改變畫面):`--at 74` 必須**逐位相同**。
功能改動(該改變畫面):`--diff` 要看到預期的值移動,而且**只有**預期的值移動。

## 三條結構規則(會擋你,而且是故意的)

`scripts/validate-architecture-boundaries.ts` + `scripts/architecture-boundaries-baseline.json`

- **R1 單一定義** —— `appearance/` 或 `constants/` 擁有的名字,全 `src/` 只能有一處宣告
- **R2 sink 不得自創身分色** —— `appearance/` 之外不得用顏色 literal 去 `??` 一個 appearance 值
- **R3 層次方向** —— `appearance/`、`constants/` 不得 import `scene|viz|ui|app|homepage`

baseline 是**棘輪不是特赦**:已知違規逐條列出,新的會紅,而且一個對不到東西的 padding row 也會讓執行失敗。
