# R1 worker report

## 工具型別錯誤

根因是 `scripts/refactor/extract-region.ts` 在 virtual target typecheck 路徑呼叫 `ts.getScriptKindFromFileName`；目前安裝的 TypeScript 型別表面沒有這個 API，因此出現 `TS2339`。

修法：加入本地 `scriptKindForFileName()`，依 `.ts/.tsx/.js/.jsx/.json` 副檔名映射到 `ts.ScriptKind`，並讓 `createSourceFile()` 使用它。另補上工具對 module-scope pure helper 的保守支援，以及只忽略 ambient `undefined` 的 capture 判定；這讓兩個 identity-color helper 能由工具移出而不放寬寫入、hook、未解析 capture 等安全閘門。並新增 top-level helper 的 real-tsc 測試案例。

驗證：

- `npx tsc --noEmit -p tsconfig.scripts.json`：`exit 0`
- `npx tsc --noEmit --pretty false`：`exit 0`
- 抽取器測試未能在本 sandbox 得到完整結果：測試內的 `spawnSync(node, tsc)` 被環境回 `EPERM`（`BASELINE_TSC_FAILED`），不是 TypeScript 診斷或 assertion failure。外層 shell 直接執行的兩個 `tsc` 已通過。
