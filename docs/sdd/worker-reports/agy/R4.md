## 總結

### 最該優先補建行為保護的前 3 條

1. **`beamDisplaySpec.showNonServingCones ? null : sinrLiveTargetSatIds` (MainScene 行 1926)**
   - **理由**：此運算式定義了「波束錐渲染預設收斂在 ≤2 顆目標衛星，同時在全視角下保留 null 逃逸」的核心渲染不變量。刪除後該幾何邊界完全失去檢查，且上方遺留了宣稱該不變量被保護的孤兒註解（殘留物）。
   - **接手方案**：建立專門針對波束目標衛星過濾邏輯的純函式單元測試。

2. **`resolveSceneLaneRenderPlan({` (MainScene 行 1647)**
   - **理由**：這是 MainScene 與泳道架構的總接線點。刪除後 MainScene 是否依據渲染計畫執行渲染管線失去靜態約束。
   - **接手方案**：以場景管線整合測試驗證 MainScene 調用 `resolveSceneLaneRenderPlan` 並套用結果。

3. **`sceneLane={sceneLane}` 傳入 `<MainScene />` 與 `<ControlBar />` (App.tsx 行 642)**
   - **理由**：App 與核心場景/控制列的泳道同步接線。若元件分解時漏傳 prop，泳道狀態將失步。
   - **接手方案**：改由 React 元件整合測試或針對標籤的精確 AST 屬性檢查接手。
