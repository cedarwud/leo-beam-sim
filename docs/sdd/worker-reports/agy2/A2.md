## 最該退回的前 3 條

1. **`validate-timeline-scrubbing.tsx:L147`（判定：`削弱`）**
   - **退回原因**：提案宣稱「已被單元測試與 jump-end 覆蓋」並建議直接刪除 source pin。單元測試只能證明 `clampTimelineTime` 函式本身的數學計算正確，但完全無法證明 `App.tsx` 在處理 scrubber 拖曳時真的有呼叫它；而 `timeline-jump-end` 僅測試點擊「跳至結尾」按鈕，無法涵蓋自由拖曳至負數或超界時間的保護。若重構時漏接或刪除了 clamp 呼叫，單元測試與 jump 測試均會持續保持綠燈，但拖曳防超界功能已實質損壞。
2. **`validate-modqn-handover-story-layer.ts:L555`（判定：`削弱`）**
   - **退回原因**：原斷言釘的是傳入每個 cell 的 UE 分布 mapping（`ueCountByCellId`）。提案將其弱化為「所有 badge 數字總和等於總數」。若重構造成 mapping 錯亂（例如所有 UE 全分給 Cell 0、其他 Cell 顯示 0，或各 Cell 均分），總和依然等於總數，此行為斷言會產生嚴重假綠，無法防護 per-cell 渲染的正確性；且前置操作還使用了不存在的 selector `advanced-setup-trigger`。
3. **`validate-phase-b-training-form.tsx:L164`（判定：`selector 無效`）**
   - **退回原因**：提案同時涉及了 3 個不可用的 selector（`advanced-setup-trigger` 與 `advanced-setup-drawer` 完全不存在於 `src/`，`lane-experience-modqn-live-cell-preview` 為死碼未掛載），且其宣稱覆蓋的現有閘門 `validate-frontend-advanced-drawer-modality-browser.ts` 與 `validate-phase-c-lane-experience-bar-browser.ts` 目前皆為紅燈，完全無法在真實執行期提供任何有效防護。
