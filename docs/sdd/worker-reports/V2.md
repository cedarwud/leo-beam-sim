# V2 — `AppWalkerSandbox` 重構報告

本輪只處理 `src/AppWalkerSandbox.tsx` 的純衍生計算候選；沒有修改
`useEffect`、`useCallback`、`MainScene.tsx`，也沒有執行任何 `*:browser`、
`check:ee` 或 `check:visual` validator。

先說明量測口徑：本 checkout 的 AST 實測是 53 個 `useState`，不是工作單上
沿用的 59。另有 17 個 `useRef`、51 個 `useMemo`、40 個 `useCallback`、26 個
`useEffect`，以及 87 個元件內部會被寫入的 binding。整個元件的 closure
analyzer 分數是 49/100；這是 triage 訊號，不是可抽取證明。`rg` 的結果會把
import／註解中的 `useState` 一起算入，所以沒有拿它當 state 數量。

## 分組與判斷

### State 依賴盤點

以下是目前 checkout 的 53 個 state binding。`主要讀取` 是它們流向的衍生節點；
`主要回饋` 是會重新寫入同一領域的 effect／callback／UI action。這份盤點先於
任何 effect 或 callback 抽取；它顯示本檔案不是單純的 `SceneRenderContent` DAG。

| 語意領域 | state binding（完整清單） | 主要讀取與回饋 |
|---|---|---|
| 資料來源與 replay 游標（9） | `sceneSource`, `showcaseArtifact`, `showcaseArtifactSource`, `showcaseLoading`, `showcaseError`, `frameIndex`, `currentTimeSec`, `replayArm`, `replayManifest` | `sceneSource` 進入 `sceneLane`、`activeSceneTopology`、`runtime`、rail；artifact/loading/error 進入 `replayController`、`replaySceneFrame`、coverage 與 rail；frame/time 由 loader、playback、seek 回寫。 |
| 模式與導覽（8） | `appMode`, `selectedProfileId`, `handoverMode`, `modqnReplayProofRequested`, `leftSidebarTab`, `leftSidebarCollapsed`, `rightSidebarTab`, `homepageCanonicalTab` | `appMode`／proof flag 與 `sceneSource` 決定 `sceneLane`；profile 進入 `baseProfile`；handover mode 進入左右 tab、rendered replay display 與 callbacks；sidebar state 主要由 UI action 回寫。 |
| training／MODQN 資料（14） | `omegaActiveForContext`, `omegaDisplayApplyVersion`, `rescalarizeFallbackCount`, `selectedUserTrainedJobId`, `bundleProvenanceKind`, `userTrainedLoadError`, `selectedTrainingServiceManifest`, `selectedTrainingRunMetadata`, `modqnVisualLayerPreset`, `modqnServiceAllocationEnabled`, `modqnReplayShellModel`, `modqnReplayEnvelope`, `modqnReplayDisplayState`, `modqnReplayVisualElapsedSec` | training metadata／env axes 進入 profile 與 topology；shell／envelope／display／elapsed 形成 replay model、visual timeline、rail、scene frame；omega apply、bundle loader、replay timer 會回寫這些 state。 |
| signal／scene runtime（9） | `beamDisplaySpec`, `reducedMotion`, `viewport`, `signalTuning`, `sceneTopology`, `sceneVisualScale`, `handoverPolicyState`, `primaryUeJogKm`, `measurementResetEpoch` | `signalTuning`、`sceneTopology`、policy、profile 形成 `signalTunedProfile` → `effectiveProfile` → `runtime`；viewport、reduced motion、display spec 進入 render/runtime；jog、reset epoch 由操作與 sim reset 回寫。 |
| live／handover presentation（7） | `liveTimelineSeekRequest`, `manualHandoverRequest`, `simState`, `liveObservedHandoverRailEvents`, `liveWalkerHandoverEventIndex`, `staleFormulaEvidenceKey`, `visibleHandover` | `simState`、manual request、visible handover 形成 teaching display；live index／observed events 形成 rail 與 director controls；seek、simulation update、handover action 會反向寫回。 |
| replay UE filter（2） | `ueDisplayCount`, `elevatedUeId` | 與 `replaySceneFrame` 形成 `processedUes`、`windowReplayCue`、active frame；由 replay/display controls 回寫。 |
| Visual Lab sandbox（4） | `vlabRefOpenModules`, `vlabRefActiveModule`, `vlabRefSelectedUe`, `sandboxSidebar2ActiveTab` | module/tab state 只服務 UI；`vlabRefSelectedUe` → UE geometry input → geometry controls，`onAngleChange` 又寫回 `vlabRefSelectedUe`，形成一個局部回饋環。 |

已確認的主要鏈如下：

1. `sceneSource + appMode + modqnReplayProofRequested → sceneLane → activeSceneTopology / signalTunedProfile / runtime / handoverRailEvents`。
2. `selectedProfileId → baseProfile → signalTunedProfile → effectiveProfile → runtime`；`handoverPolicyState` 會插入 effective profile，並由 reset／experience handlers 回寫。
3. `showcaseArtifact → replayController / replaySceneFrame → processedUes / coverage / rail`，而 `frameIndex + currentTimeSec` 同時由播放、初始時間與 seek 路徑寫回。
4. `modqnReplayEnvelope + modqnReplayShellModel + modqnReplayVisualElapsedSec → visual timeline / replay rail / rendered display`，omega apply 與 replay effects 又會更新同一資料域。
5. `liveWalkerHandoverEventIndex → handover rail → director controls → seek/manual handover → simState / event index`；這不是單向顯示投影。
6. `signalTuning / sceneTopology / handoverPolicyState → runtime → sim reset / evidence key`，再由 controls、effects、training load 改回輸入。
7. `vlabRefSelectedUe → pure geometry controls → onAngleChange → vlabRefSelectedUe`。

因此本檔案的純 `useMemo` 子圖確實有可抽接縫，但 effect／callback 圖含有
多個跨領域回饋環。這次不把這些環誤包成大 hook；在狀態所有權未收斂前，
`cancelled`、`cached`、`initialTimeSec`、`handleTimelineSeek` 和模式／handover
handlers 都判定為不該抽。

## 我判斷不該抽的

- `cancelled`／`cached` 等 `useEffect`：它們擁有 cancellation flag、fetch/cache
  生命周期與多個 setter；需要把 state ownership 一起設計，不是把宣告搬到 hook。
- `initialTimeSec`：同時讀取 homepage canonical analysis、replay controller、
  timeline descriptor，並設定 frame/time／ref，是初始時間協調器，不是純數值函式。
- `handleTimelineSeek`：計畫雖可被 AST 讀出，但有 12 個輸入，會 reset analysis、
  送 live request、更新 replay elapsed 與 rail 狀態；目前的回饋環使它不適合抽。
- `runtime`：它是 profile、scene topology、camera command、timeline request、
  viewport 與 sim reset 的匯流根；17 個輸入已是架構警訊，且 extractor 明確回報
  `UNRESOLVED_IMPORT`，不繞過。
- `handoverEventRail`：這是 JSX UI tree，包含 rail 與 Director controls 的呈現／
  callback wiring；應在 UI component seam 處理，不應用純計算 hook 偽裝。
- `vlabRefUi` 與 `timelineBar`：前者是 locale copy，後者是 UI composition；兩者
  沒有值得建立 domain pure function 的邊界。
- 其餘 data loader、scenario preset、mode controller、handover presentation
  handlers：有寫入捕獲或跨 state 協調；目前抽取會複製參數網與 stale closure 風險。
