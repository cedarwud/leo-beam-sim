1. **第 1 優先（純衍生計算 / Pure Derived Calculations）**：輸入為唯讀 props/state，輸出為記憶化數值或物件，**完全無 `setState` 寫入捕獲**，參數小於 10 個。這是自動化抽取工具（`tsc` 保證安全回滾）最安全、回報最立竿見影的目標。
2. **暫緩處理（有寫入捕獲 / Write Capturing）**：大量 `handle*` 與 `useEffect`。抽取這類程式碼必須一併封裝內部 state，否則只會製造出「傳入 20 個 setter」的怪胎 hook。這需要架構重構，不該當作機械搬移。
3. **拒絕抽取（Anti-patterns）**：偽裝成變數的 JSX 節點（該抽成 Sub-component）、3D Render Loop 命令/補間動畫（該抽成獨立 Subsystem）。

## 我認為不該抽的

以下幾組宣告**嚴禁**使用「抽出自訂 hook」的工具直接搬移，否則只是把壞味道轉移到別的檔案：

1. **偽裝成變數的 JSX 節點（UI 樹碎片）**
   * **宣告**：`renderedLiveSatelliteMarkers` (MainScene, L2552, 58行)、`handoverEventRail` (Sandbox, L2215, 47行)、`timelineBar` (Sandbox, L2265, 19行)。
   * **原因**：從命名與行數來看，這極可能是直接在主函式本體內宣告的 JSX 變數（例如 `const timelineBar = <div ...>...</div>`）。**JSX 不屬於 Hook，應該被重構成標準的 React 子元件**（如 `<TimelineBar />`、`<LiveSatelliteMarkers />`），透過 props 傳遞資料，而不是抽進自訂 hook 裡回傳 JSX。

2. **命令模式與 3D 渲染迴圈機制（Imperative Render Loop）**
   * **宣告**：`tween` (MainScene, L4458, 65行)、`command` (MainScene, L4356 & L4391, 共 88行)、`nowMs` (L2706, 54行)、`readApexWorld` (L2793, 25行)。
   * **原因**：這通常是 Three.js / 3D Engine 的即時補間動畫、每一幀的時間抽樣（tick）、或是寫入 Command Queue 的指令。這類程式碼帶有隱蔽的時間狀態或 Imperative API 呼叫，硬抽成 hook 會引發嚴重的閉包不同步（stale ref）或跳幀。這需要的是「場景動畫/指令子系統（Subsystem）」的物件架構重構，不是搬家。

3. **匿名宣告**
   * **宣告**：`AppWalkerSandbox` 中的 `(anon)` (L1984-2013, 30行)。
   * **原因**：缺少明確的語意邊界與職責定義。未確認其真實意圖前，強抽必然製造出無意義的模組名稱（如 `useAnonymousBlock`）。
