## 無法轉換的

### `validate-modqn-handover-story-layer.ts:L558`

`data-modqn-handover-cues-visible` 真實存在，但它與 `visible={showCellReassignmentEventArcs}` 使用同一個上游旗標，沒有讀取實際 `CellHandoverArcs` scene subtree。若 JSX prop 在分解時掉了，該 dataset 仍照樣切成 `1`，所以不能用。此項仍是 runtime 行為（暫不建議改判 S/V），但轉換前必須先有從實際 arc object/mesh 導出的 canvas telemetry。

### `validate-modqn-handover-story-layer.ts:L562`

現有 cell-beam-cone scope/count/satellite-count 是在 `MainScene` 呼叫同一 resolver 事先算出的 model telemetry，不是 `CellBeamCones` 實際掛載結果。刪掉或接錯 `beamConeScope` prop 時，dataset 可以繼續報「正確」而畫面實際用 component default，會造成假綠。保留為 B 的待辦，先補 mesh-derived 觀察點。

### `validate-phase-h-s8-hud-camera-default.ts:L41`

`paper-faithful-closeup` 只有型別與 pose record，`src/` 沒有按鈕、select option 或任何命令會要求此 preset。它目前不是可進入的應用行為。若它是刻意保留的程式介面，改判 S，以 `CameraPreset`/pose 單元測試守契約；若已無 consumer/需求，改判 V。現有 `validate-phase-c-camera-preset.tsx` 雖守住字串與 pose，但仍屬 source-shape，不算 runtime 覆蓋。

### `validate-phase-i-s5b-cell-beam-cones.tsx:L379`

與 L562 是完全相同的 prop wiring，且同樣缺少獨立、mesh-derived runtime 訊號。不能把同一組 model-derived canvas attributes 當成兩份行為證據。保留為 B 待辦，未來一條真正的 cone mesh gate 可同時取代兩個 source pins。

### `validate-phase-g-ue-mobility-step.tsx:L262`

現有 canvas 只暴露 primary UE 位置，而 runtime mobility 明確不移動 primary；secondary UE 的位置、位移量與 trail point count 都沒有 DOM/canvas dataset。現有 handover rail index 是 App 的平行計算，會在 MainScene wiring 斷掉時仍然變化，不可拿來代理。此項仍是 B，但必須先建立 secondary-UE 實際 render telemetry 才能轉。
