# M1：`extract-region` 的自訂 hook 形狀

## 我加了什麼

`scripts/refactor/extract-region.ts` 現在支援明確指定 `shape: 'hook'`，CLI 對應為 `--shape hook`。
輸入仍是來源檔、inclusive 行號區間、目標模組與 hook 名稱。新增的 `--plan` 是唯讀模式：它會先列出要搬的 hook 宣告、會跟著搬的寫入 statement、必要參數、回傳 binding 與拒絕理由，不建立或修改任何檔案。

目前可自動執行的能力邊界如下：

- 接受同一個 component/custom hook body 內、hook 次序連續的頂層 `useState`、`useRef`、`useMemo`、`useCallback` 變數宣告。
- 以 TypeScript symbol 分析所選 binding 在區域內外的使用與寫入。區域內可完整搬走的頂層 expression statement 會跟著 hook 宣告移入新模組；區域外仍需使用的 state/value/ref/setter 會由 hook 回傳。
- 產生 `...Parameters` 與 `...Result` 型別、目標 hook、來源端 `const { ... } = useXxx({ ... })`，並重定基相對 import 與 inline `import("...")` 型別。`node_modules/@types/react` 的型別會正規化成 `import("react")`，不寫入 checkout 絕對路徑。
- execute 模式先跑 baseline `tsc --noEmit`。只有 baseline 綠且 plan 可執行才寫檔；寫後再跑一次 `tsc --noEmit`。紅燈時以寫入前保存的來源文字 byte-exact 還原來源、刪除本次新建目標與可安全移除的空目錄，不使用 git。
- AST 行號邊界不完整、間接寫入無法精確歸屬、binding/參數循環、或合併後會改變 React hook 次序時，均在寫檔前拒絕並說明原因。

## archived 叢集的執行計畫

唯讀 plan 指令：

```text
node --import tsx/esm scripts/refactor/extract-region.ts --shape hook --plan --file src/App.tsx --start 2358 --end 2384 --target src/app/useArchivedTleTimeline.ts --symbol useArchivedTleTimeline --project tsconfig.json
```

工具分析出的搬移內容：

| 原行號 | hook / statement | binding |
|---|---|---|
| L2358–2371 | `useMemo` | `archivedTleTimelineDescriptor` |
| L2379 | `useRef` | `archivedTleTimelineCurrentTimeRef` |
| L2380 | 區域內直接寫入，跟著搬 | `archivedTleTimelineCurrentTimeRef.current = timelineCurrentTimeSec` |
| L2381–2383 | `useRef` | `archivedTleSelectTimelineTimeRef` |
| L2384 | 區域內直接寫入，跟著搬 | `archivedTleSelectTimelineTimeRef.current = homepageCanonicalAnalysis.selectTimelineTimeSec` |

工具推導的參數：

- `homepageCanonicalAnalysis: HomepageCanonicalAnalysisState`
- `timelineCurrentTimeSec: number`

工具推導的回傳值：

- `archivedTleTimelineDescriptor: TimelineSurfaceDescriptor`：原處 L2375 仍使用。
- `archivedTleTimelineCurrentTimeRef: RefObject<number>`：區域外 L2420、L2446 寫入，其他位置亦讀取；ref identity 必須回傳。
- `archivedTleSelectTimelineTimeRef: RefObject<((targetSec: number) => void) | undefined>`：區域外 L2421、L2457 使用。

plan 結果為 `ready: false`，拒絕理由是：

```text
CYCLIC_DEPENDENCY: Parameter timelineCurrentTimeSec depends on a selected hook return, so no legal call site can satisfy both declarations.
```

具體循環是：`useArchivedTleTimeline` 若要建立 current-time ref，就需要 `timelineCurrentTimeSec`；但原處的 `timelineCurrentTimeSec` 來自 `activeTimelineDescriptor.currentTimeSec`，而 `activeTimelineDescriptor` 在 archived 模式又需要該 hook 應回傳的 `archivedTleTimelineDescriptor`。把 hook call 放在前面會先使用尚未宣告的 `timelineCurrentTimeSec`；放在後面則會先使用尚未取得的 `archivedTleTimelineDescriptor`。工具沒有擴張 owner 指定的三個 binding、沒有重排 hook，也沒有猜測新的 ownership boundary，因此依規格拒絕。

## 實際執行結果

execute 指令：

```text
node --import tsx/esm scripts/refactor/extract-region.ts --shape hook --file src/App.tsx --start 2358 --end 2384 --target src/app/useArchivedTleTimeline.ts --symbol useArchivedTleTimeline --project tsconfig.json
```

結果：工具內建的 baseline `tsc --noEmit` 通過，接著在任何寫入前以 `CYCLIC_DEPENDENCY` 拒絕，process exit 1。因為 mutation 尚未開始，所以沒有 post-extraction `tsc`、也不需要回滾；這不是「回滾成功」，而是「零寫入拒絕」。

- `src/App.tsx`：4,642 行 → 4,642 行。
- 執行前後 SHA-256 都是 `d81f86afe96e97ede7abea6e4803205e93da6c18010d907f7f25120f3445f775`。
- `src/app/useArchivedTleTimeline.ts`：執行前不存在，執行後仍不存在。

因此這個真實案例沒有完成搬移；有效結果是工具證明 owner 指定的三-binding 邊界本身形成呼叫參數循環，必須由強模型/owner 另選較大的 ownership boundary，不能由工具偷偷擴張。

## 這個形狀仍然無法處理的

- 不自動搬 `useEffect`、`useLayoutEffect`、`useReducer` 或任意 custom hook；目前只接受工作單指定的四種 primitive hook。
- 不接受 conditional/nested hook，也不接受在所選 hooks 之間夾有未選 hook；工具不嘗試證明複雜 control flow 下的 React hook order。
- 區域內寫入只有在能歸屬到完整、頂層 expression statement 時才搬。透過 alias/local callback 傳播而無法精確定主的間接寫入會拒絕，不會猜測 side effect。
- 不會為了讓 plan 成立而擴張範圍、搬走額外衍生 state、重新設計 ownership，或把 module-local declaration 自動改成 export。
- 分析仍是 flow-insensitive 靜態分析；dynamic dispatch、accessor、imported function 的隱藏 mutation、custom-hook 內部效果與外部物件 alias 不在可證明範圍，遇到可見風險時 fail closed。
- `--plan` 只做 AST/symbol 分析，不宣稱可編譯；只有 execute 模式的 baseline/post `tsc` 才是編譯網。目標檔已存在時 execute 仍拒絕覆寫。
