# V3 EE classroom lab guide: T1–T6

This guide follows the current V3 Project UI labels. The main tuning button is
`EE`; its accessible tab label is `Energy Efficiency` / `能源效率`. The teaching
card is `Energy breakdown` / `耗能明細`. The canonical section is
`ADR-003 Canonical System EE` / `ADR-003 標準系統能源效率`.

All numeric ranges and visual observations marked `PROVISIONAL` are derived from
the current source controls and have not been browser-verified in this recovery
worker. Do not turn a provisional range into a hard classroom conclusion until
the browser gate is run.

## T1 — Verify the teaching power chain

**Purpose**

Verify the visible teaching chain `P_RF → P_PA → P_total` and that the restored
teaching circuit default is exactly `3 W`.

**Prediction**

`P_total = P_PA + P_circuit`. Restoring energy defaults makes
`Circuit power P_circuit` read `3 W`; it does not create canonical `P_sys`.

**Time**

Accumulate for 20 s (`PROVISIONAL`: classroom timing suggestion, not browser-verified).

**Reset**

First click `Restart measurement` / `重新開始量測`. If any energy knob is
non-default, click `Restore energy defaults` / `恢復能源參數預設` before starting
the observation. These are separate actions.

**Start**

Open the left tuning drawer, select the `EE` main tab, and confirm the visible
heading `Single-link Power Model (Teaching Knob)` / `教學參數：單一連線功率模型`.

**Exact inputs**

- `Per-beam transmit power`: `24 dBm` (control range `10–60 dBm`, step `0.5`; `PROVISIONAL`).
- `PA efficiency η_PA`: `0.35` (range `0.05–1`, step `0.01`; `PROVISIONAL`).
- `Circuit power P_circuit`: `3 W` (range `0–100 W`, step `1`; `PROVISIONAL`).
- `Energy per handover e_HO`: `3 J` (range `0–500 J`, step `1`; `PROVISIONAL`).

**Step-by-step operation**

1. In the `SINR` main tab, open `Transmit Power` and set `Per-beam transmit power` to `24 dBm`.
2. Select `EE`, set `PA efficiency η_PA` to `0.35`, `Circuit power P_circuit` to `3 W`, and `Energy per handover e_HO` to `3 J`.
3. Click `Restart measurement`, resume playback, and wait for the time above.
4. Read `RF transmit power`, `PA input power`, `Circuit power`, and `Total power` in `Energy breakdown`.

**Observations and ranges**

Record the four displayed rows and their units. At the specified inputs the
source calculation predicts approximately `P_RF=0.251 W`, `P_PA=0.718 W`, and
`P_total=3.718 W` (`PROVISIONAL`; browser display not verified).

**Direction and reason**

Raise `Circuit power P_circuit` by `1 W`. `Total power` should rise by `1 W`
while `P_RF` and `P_PA` stay unchanged, because the circuit term is added after
the PA conversion.

**Record**

Record the four power values, the exact slider values, `Elapsed`, and whether
the visible `teaching-scope-note` says `non-canonical`.

**Interpretation**

The power identity is an identity of the teaching model only. `P_total` is not
the ADR-003 `P_sys`, even when the unit is W.

**Pass**

The chain is visible, the sum is numerically consistent within display
rounding, the circuit default is `3 W`, and the scope note explicitly says
`non-canonical`.

**Common recovery**

If the circuit value is not `3 W`, click `Restore energy defaults`; if only the
accumulated rows are stale, click `Restart measurement`. Do not use the SINR
`Reset` button as an energy reset.

**Teacher answer**

At `24 dBm`, `P_RF = 10^(24/10)/1000 ≈ 0.251 W`; with `η_PA=0.35`,
`P_PA≈0.718 W`; adding the `3 W` teaching knob gives `P_total≈3.718 W`.
This is a single-link classroom chain, not the canonical system boundary.

## T2 — Separate PA efficiency, circuit power, and handover cost

**Purpose**

Show which knob changes instantaneous power and which knob changes only the
accumulated handover-energy term.

**Prediction**

Increasing `PA efficiency η_PA` lowers `PA input power`; increasing `Circuit
power P_circuit` raises `Total power` one-for-one; increasing `Energy per
handover e_HO` changes `Handover energy` only when a handover is counted.

**Time**

Use two 20 s windows (`PROVISIONAL`; browser-unverified): one baseline and one
perturbed window.

**Reset**

Click `Restart measurement` between baseline and perturbed observations. Keep
the energy parameters unchanged for that comparison.

**Start**

Use the `EE` tab with `Per-beam transmit power=24 dBm`, `PA efficiency η_PA=0.35`,
`Circuit power P_circuit=3 W`, and `Energy per handover e_HO=3 J`.

**Exact inputs**

- Baseline: `η_PA=0.35`, `P_circuit=3 W`, `e_HO=3 J`.
- Perturbation A: `η_PA=0.70`, with the other two values unchanged.
- Perturbation B: restore `η_PA=0.35`, set `P_circuit=12 W`.
- Perturbation C: restore `P_circuit=3 W`, set `e_HO=100 J`.
- The ranges `η_PA 0.05–1`, `P_circuit 0–100 W`, and `e_HO 0–500 J` are `PROVISIONAL`.

**Step-by-step operation**

1. Run the baseline for the time above and record `PA input power`, `Total power`, `Handover count`, `Handover energy`, `Total energy`, and `Run-accumulated EE`.
2. Click `Restart measurement`, set perturbation A, and repeat.
3. Repeat for perturbations B and C, restarting the measurement window each time.
4. Use the visible power and energy sum hints to check each decomposition.

**Observations and ranges**

For A, `PA input power` should be lower than baseline while `Circuit power`
stays `3 W` (`PROVISIONAL`). For B, `Total power` should be baseline plus
`9 W` (`PROVISIONAL`). For C, `Handover energy` should be
`Handover count × 100 J` when the count is measured; if no handover occurs it
is a measured `0`, not a missing value.

**Direction and reason**

Higher η reduces `P_RF/η`; higher circuit power adds directly to `P_total`; e_HO
does not belong to instantaneous `P_total` and is charged in the run-energy
denominator as `E_HO`.

**Record**

Record a row per condition with all three knob values, `Handover count`,
`Handover energy`, `Total energy`, and `Run-accumulated EE`. Mark any no-service
or missing reading as the displayed dash rather than zero.

**Interpretation**

`Run-accumulated EE` is the teaching ratio of accumulated data to accumulated
teaching energy. It is not the canonical `EE_eval` until a canonical producer
value is wired.

**Pass**

The three causal directions are observed or, when no handover occurs, the guide
records the explicit no-event limitation. No knob is described as changing
canonical `P_sys`.

**Common recovery**

If a comparison includes old samples, click `Restart measurement` and repeat.
If the parameter itself is wrong, use `Restore energy defaults`, then re-enter
the exact condition.

**Teacher answer**

η_PA and P_circuit are instantaneous teaching power terms. e_HO is an event
price used by `E_HO = N_HO × e_HO`; it must not be silently folded into a
single-link instantaneous `P_total` row.

## T3 — Trace transmit power, bandwidth, reuse, and live SINR to throughput

**Purpose**

Trace the route from the `SINR` controls to the teaching throughput row while
keeping the signal experiment distinct from the energy scope label.

**Prediction**

The teaching formula is `R = (B / K) · log₂(1 + SINR)` with an 8 bit/s/Hz cap.
Changing B also changes the thermal-noise term, while changing K changes both
co-channel grouping and the B/K allocation; therefore the observed direction
must be recorded rather than assumed from one factor alone.

**Time**

Use 15 s per setting (`PROVISIONAL`; browser-unverified).

**Reset**

Click `Restart measurement` before each B/K/P_t condition so the teaching
accumulation does not mix settings.

**Start**

Open `SINR`, choose `Transmit Power` for P_t, `Thermal Noise` for B, and
`Interf.` for K. Then return to `EE` and observe `Throughput` in `Energy breakdown`.

**Exact inputs**

- `Per-beam transmit power`: `24 dBm`, range `10–60 dBm`, step `0.5` (`PROVISIONAL`).
- `Channel bandwidth B`: `100 MHz`, range `5–400 MHz`, step `5` (`PROVISIONAL`).
- `Frequency reuse factor K`: `1`, then `3`; options are `1…7` (`PROVISIONAL`).
- SINR is a live readout from the scene, not a direct input control.

**Step-by-step operation**

1. Set `P_t=24 dBm`, `B=100 MHz`, and `K=1`; restart the measurement.
2. Record the live `Signal quality` / SINR and `Throughput`.
3. Set `K=3`, restart, and record the same rows.
4. Restore `K=1`, set `B=200 MHz`, restart, and record again.
5. If the scene permits, set `P_t=30 dBm`, restart, and record the effect on SINR and throughput.

**Observations and ranges**

Record the exact displayed SINR and throughput for every condition. The source
control ranges above are `PROVISIONAL`; the live SINR range is scene-dependent
and must not be hard-coded. A dash means the current sample is unavailable.

**Direction and reason**

Higher P_t generally raises desired signal and co-channel interference together;
the resulting SINR direction is scene-dependent. Higher K reduces same-group
interference but also divides B across more reuse groups. Higher B raises the
nominal numerator bandwidth but also raises σ²=N₀B. Explain the measured result
using both effects.

**Record**

Record `P_t`, B, K, live SINR, `Throughput`, and the reset time for each row.

**Interpretation**

This experiment changes the numerator/denominator of the live SINR and the
teaching throughput numerator. It does not turn the teaching `P_total` into
canonical `P_sys`.

**Pass**

Every condition has a separate measurement window, exact inputs, an observed
SINR/throughput pair or an explicit dash, and a causal explanation that names
both B/K allocation and thermal/interference effects where relevant.

**Common recovery**

If the value appears unchanged, verify that the intended sub-tab is active and
that `Restart measurement` was clicked after the change. Do not infer a missing
SINR from a zero throughput.

**Teacher answer**

The control chain is `P_t → live SINR`, and `B,K,SINR → R`. The exact direction
of B or K in a live scene is not a universal monotonic claim because each also
changes a different term of the model.

## T4 — Distinguish measurement reset from energy-parameter restoration

**Purpose**

Verify that `Restart measurement` and `Restore energy defaults` have different
ownership and visible effects.

**Prediction**

`Restart measurement` clears only the cumulative window and preserves all
parameters, scene, playback, and simulation time. `Restore energy defaults`
changes η_PA, P_circuit, and e_HO back to model defaults; changing an energy
parameter is a new ledger experiment and can reset the keyed measurement window.

**Time**

Accumulate 15 s before and after each action (`PROVISIONAL`; browser-unverified).

**Reset**

Do not click either reset until the pre-reset values have been recorded. The
two exact labels are `Restart measurement` and `Restore energy defaults`.

**Start**

On `EE`, set non-default values and wait until `Elapsed`, `Cumulative delivered
data`, or `Total energy` is non-zero.

**Exact inputs**

- `PA efficiency η_PA=0.60`.
- `Circuit power P_circuit=25 W`.
- `Energy per handover e_HO=100 J`.
- The three control ranges are `PROVISIONAL`: η `0.05–1`, circuit `0–100 W`, e_HO `0–500 J`.

**Step-by-step operation**

1. Enter the exact values and accumulate for the time above.
2. Record every energy control and the cumulative rows.
3. Click `Restart measurement`; immediately re-check the three controls and the cumulative rows.
4. Accumulate again, then click `Restore energy defaults`.
5. Re-check the controls and note whether the changed energy key caused a fresh measurement window.

**Observations and ranges**

After `Restart measurement`, the controls should remain `0.60`, `25 W`, and
`100 J`, while cumulative rows restart (`PROVISIONAL` browser expectation).
After `Restore energy defaults`, controls should read `0.35`, `3 W`, and `3 J`
(`PROVISIONAL` browser expectation). No action should change scene topology or
playback state.

**Direction and reason**

The first action mutates only the ledger epoch. The second mutates the energy
parameter state; the ledger reset key treats a changed energy experiment as a
new window, which prevents sums from crossing parameter conditions.

**Record**

Record before/after values, simulation clock, playback state, and whether each
button changed the parameter controls.

**Interpretation**

“Reset” is not one overloaded operation: one restarts observations, the other
restores model inputs. The UI must keep those meanings separate.

**Pass**

The two buttons are visible and distinct; `Restart measurement` preserves the
three parameter values; `Restore energy defaults` restores `η_PA=0.35`,
`P_circuit=3 W`, and `e_HO=3 J`.

**Common recovery**

If a parameter unexpectedly remains altered, click `Restore energy defaults` and
confirm all three controls. If only totals are stale, use `Restart measurement`
without changing the controls.

**Teacher answer**

The explicit teaching default is `circuitPowerW=3 W`. It is not a canonical
system-power input, and neither reset action is allowed to manufacture a
canonical readout.

## T5 — Check fail-closed SINR semantics

**Purpose**

Verify the boundary between an explicit no-service sentinel and a broken SINR
expression.

**Prediction**

Only `-Infinity` means no service and produces throughput `0`. `NaN` and
`+Infinity` fail closed to `null`; they must not be laundered into measured zero
throughput or accumulated data.

**Time**

No browser timing is required. This is a model/UI release test; any live timing
claim is `PROVISIONAL`.

**Reset**

For a live UI check, click `Restart measurement` before injecting or replaying a
test frame. The ordinary browser controls do not accept NaN or Infinity.

**Start**

Use the project test runner from the V3 project directory. The visible UI
surfaces are `Throughput`, `Elapsed`, `Cumulative delivered data`, and the
canonical status/identity rows.

**Exact inputs**

Run:

```text
node --import tsx/esm src/teaching/energyModel.test.ts
```

The exact model inputs are `bandwidthMHz=20`, `frequencyReuse=1`, and
`sinrDb ∈ {-Infinity, NaN, +Infinity}`. There is no browser slider range for
this sentinel test.

**Step-by-step operation**

1. Run the command above.
2. Confirm the `-Infinity` case returns `0`.
3. Confirm the `NaN` case returns `null`.
4. Confirm the `+Infinity` case returns `null`.
5. Confirm the App path sends only finite SINR to the quality ledger; the explicit `-Infinity` no-service state is not counted as a usable low-SINR sample.

**Observations and ranges**

Expected model results are `0`, `null`, and `null` respectively. These are
source/test results, not browser ranges. A UI dash for a failed value is the
correct absent state; a displayed `0` is correct only for measured no-service.

**Direction and reason**

`-Infinity` is a domain sentinel. NaN and +Infinity are non-finite failures and
would poison logarithms or quality statistics, so the App and helper fail closed.

**Record**

Record the exact command, exit status, test count, and the three returned values.

**Interpretation**

“No service” and “the computation broke” are different claims. The UI must not
collapse them into the same measured zero.

**Pass**

The focused test passes; NaN/+Infinity do not advance the ledger; only
`-Infinity` maps to zero throughput.

**Common recovery**

If a broken reading appears as `0`, inspect the input gate and rerun the focused
test. Do not patch the UI formatter to hide the distinction; preserve null as a
dash.

**Teacher answer**

Fail-closed is an evidence rule: an absent or invalid sample is not evidence of
zero traffic. The only accepted zero here is the explicit no-service sentinel.

## T6 — Read the live canonical gate without confusing it with the teaching chain

**Purpose**

Read the live ADR-003 projection from the full `SinrLiveCellFrame`: status, the
sum identity, per-user contributions, instantaneous EE, and ratio-of-sums EE.
The card is a compact view of the producer; it does not rebuild a frame or reuse
the teaching energy knobs.

**Prediction**

The first frame after mount, reset, or seek is an instantaneous baseline:
`Producer status` is `VALID` or `ZERO-ACTIVITY`, the identity is `PASS`, and
`EE_eval` is `—`. After one strictly positive simulation-time interval,
`EE_eval` appears and is the producer's ratio of accumulated sums. Equal
timestamps do nothing; a backward/wrap or explicit seek starts a new baseline.

**Time**

One baseline observation plus one positive-dt observation. Any browser timing or
numeric range is `PROVISIONAL` until browser acceptance and empirical closure.

**Reset**

Use `Restart measurement` to clear both teaching and canonical observation
windows while preserving every parameter, scene, and playback setting. Use
`Restore energy defaults` only to restore the separate teaching knobs; it is not
a canonical input reset.

**Start**

Open `EE` and locate `ADR-003 Canonical System EE`. Read the visible scope note
before reading the rows. Let the live scene publish at least two frames.

**Exact inputs**

The publisher passes the untouched full `SinrLiveCellFrame` to the final v2
producer and supplies:

- live `bandwidthMHz` and integer `frequencyReuse` from the effective profile;
- actual per-beam `rfOutputPowerDbm` from `resolveMaxTxPowerDbm(profile.channel)`;
- the explicit effective-profile `channel.maxTxPowerDbm` converted to the
  producer's rated `P_max` in watts;
- frame `simTimeSec` for the ratio-of-sums accumulator;
- the replay seek key and an explicit measurement-reset epoch for re-anchoring.

The `3 W` `Circuit power P_circuit` control is explicitly **not** an input for
canonical `P_sys`. If the effective profile does not carry an explicit rated RF
cap, the projection stays pending/invalid with a typed code; it never promotes
the resolver fallback or invents a root-scenario cap.

**Step-by-step operation**

1. Open `EE` and read `ADR-003 partial-payload scope`.
2. At the first live frame, confirm `VALID` or `ZERO-ACTIVITY`, `PASS` for
   `Σ_u r_{1,u} = EE_inst`, and `—` for `EE_eval`.
3. Advance playback until `simTimeSec` increases strictly; confirm the same
   status/identity surface, preserved per-user contribution rows, and a numeric
   ratio-of-sums `EE_eval`.
4. Press `Restart measurement`, then confirm the next frame is a baseline again:
   `EE_eval` returns to `—` without changing the parameters.
5. Confirm the teaching area still labels `P_total` / `Run EE` as
   `non-canonical`, and that the old mean-of-ratios card and `596.92` are absent.

**Observations and ranges**

Record the exact status, identity, `P_sys`, `EE_inst`, contribution sum,
per-user rows, and whether `EE_eval` is baseline-absent or post-sample-present.
Missing/invalid rated-cap input is the only expected pending/invalid branch;
zero activity remains a measured zero state. Producer unit/range claims and all
browser-unverified visual observations remain `PROVISIONAL`.

**Direction and reason**

The canonical producer computes per-active-beam payload power, sums it to
`P_sys`, computes `r_{1,u}=R_u/P_sys`, checks
`Σ_u r_{1,u}=EE_inst`, and accumulates `EE_eval` as a ratio of sums. The UI must
preserve those fields rather than substitute the teaching knob or a mean of
instantaneous ratios.

**Record**

Record the exact labels, status, identity state, per-user rows, baseline dash,
post-sample `EE_eval`, reset result, and any typed pending/invalid error code.

**Interpretation**

`P_sys` is the ADR-003 partial-payload system boundary. Each `r_{1,u}` is an
additive accounting contribution using the shared `P_sys` denominator, not a
user's physical transmit power. `EE_eval` is
`Σ_t Σ_u R_u Δt / Σ_t P_sys Δt`; it is not the old mean-of-ratios quantity and
not the teaching `Run EE` chain.

**Pass**

The source/build and focused integration tests are green; the live publisher
uses the full frame; status, identity, `P_sys`, `EE_inst`, contributions, and
ratio-of-sums `EE_eval` reach the card; baseline/reset/seek rules hold; and no
`3 W` teaching dependency or old `EnergyEfficiencyCard` path is present. Browser
acceptance and empirical closure remain separate gates.

**Common recovery**

Do not reconstruct a fake frame from `perUePositions`, do not publish the full
frame into `SimState`, and do not use `3 W` as `P_sys`. Inspect the typed error
code and rated-cap source, then re-run the producer and focused publisher tests.

**Teacher answer**

The canonical readout is a live producer projection: `P_sys` prices the active
beam/satellite boundary, each `r_{1,u}` shares that denominator, and `EE_eval`
is the ratio of integrated data to integrated canonical energy. A baseline dash
is an intentional no-sample state, while a measured zero-activity frame is an
explicit producer result.
