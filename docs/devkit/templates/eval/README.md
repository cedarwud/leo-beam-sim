# 模板 eval — 回歸測試協議

**規則（藍圖 §11）**：任何模型改任何模板，上線前必過該模板的 eval。把「驗證不自驗」套用到制度檔自己身上。

## 執行協議（改模板的人照做）

1. 用 eval 檔裡的「樣本情境」填出完整派工 prompt。
2. 逐條核對「結構斷言」。**grep 只做初篩**：涉及禁令、唯讀、範圍、門檻的斷言必須語意判定「約束是否仍為絕對式」——「唯讀任務」改成「盡量唯讀」grep 仍命中「唯讀」但語意已弱化，這類滑坡由第 3 步 fresh agent 判，不得只憑字串比對放行。
3. 派一個 fresh-context Haiku/Sonnet agent 讀填好的 prompt，回答「模擬回報會長什麼樣」，對照「模範回報性質」逐條判 PASS/FAIL。
4. 任一 FAIL → 模板改動不得上線；修到全 PASS 或放棄改動。
5. eval 本身要改（斷言過時）→ 視同模板改動，走同協議＋在 commit message 說明為何鬆動。

**輸入／評分分離（v0.22）**：派「生成端」（填模板或模擬回報的 agent）時只給樣本情境，**不給結構斷言與模範性質清單**——同檔混放會迫使生成端讀到評分準則（污染）。評分由另一個 agent 或 controller 拿斷言清單做。

## 通用結構斷言（五個模板都適用）

- [ ] 含 `<goal>`、`<acceptance>`、`<report_format>` 三區塊（XML 標籤存在）
- [ ] goal 含動機句（「動機：」或 why 等價物）
- [ ] report_format 要求「結論先行」與「長產物落檔傳路徑」精神（禁全文傾印）
- [ ] 無「只報重要的」類質化過濾指令（審查漏報反模式）
- [ ] 唯讀類模板（search/research/review）含明確唯讀約束
