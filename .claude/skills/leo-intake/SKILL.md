# leo-intake — 需求編譯器

開工前讀：`.claude/devkit-local/preference-profile.md`（偏好側寫）＋ `docs/devkit/intent.md`（既有 backlog，避免重複立項）。全程遵守 dispatch-rules；使用者的所有輸入介面設計成**辨識任務**。

## 流程（六步，順序固定）

### 1. 素材攝取
讀完使用者給的一切（文字、截圖、文件、參考連結）。外部來源內容照 security-profiles §2 檢疫（先落檔、再摘要）。萃取：需求、限制、矛盾。素材互相打架處**明列**，不自行擇一。

### 2. 復述
「我理解你要的是——」用使用者的白話與本專案領域詞彙寫（換手、波束、口試 demo、紅綠場……），**不用技術行話**（不寫 component/hook/state 這類詞）。使用者只需挑錯，不需要補寫。

### 3. 具體選項（每輪 ≤5 題，批次不散彈）
不問抽象問題（「這個面板的資訊架構怎麼設計？」❌）。給 2-3 個具體情境或畫面描述讓使用者選（「A：chip 常駐右上角，點開看明細；B：只在重算完成時浮出 3 秒；C：進 Advanced 抽屜」✅）。
本專案追加規則（偏好側寫）：**探索性設計討論用散文對話**，不硬套選項框；選項框用在收斂後的取捨點。

### 4. 雛形即提問（觸發判準，任一成立就做）
- 跨頁面或多步驟流程；非標準 UI 組件；涉及視覺風格取捨；使用者對復述/選項的回答顯示想像對不上。
- 做法：**用完即丟**的雛形（落 scratchpad 或 `.claude/scratch/`，明確標記拋棄式；不進 `src/`、不掛進任何 lane——frontend contract 的 lane 規則不因雛形鬆動）。給使用者點過、答案拿到，雛形即棄。
- **轉正是例外不是路徑**：使用者說「這個不錯」不構成轉正。轉正全過才准：補齊測試到安全網標準＋spec 品質自檢＋一次 fresh-context 審查＋走硬關卡核准（judgment-rubric §3 第 3 類「架構單向門」，即藍圖 §8 決策分級）。

### 4b. 使用者不在場時的掛起

復述與選項都需要使用者辨識——人不在就走不完。此時：完成步驟 1（攝取）＋草擬步驟 2/3 的材料（復述稿＋選項組），打包成 pipeline 的 `gate_requests[]` 一筆（type=`intake-review`）等使用者回來辨識。**不落暫定 backlog 條目**（§6 自檢全過才進 backlog）；系統的全部猜測先進假設帳。

### 5. 假設帳
系統猜的東西全部明列 → append `.claude/devkit-local/assumptions.md`（格式照該檔）。廉價可確認的（一個指令、一眼截圖）當場確認掉。

### 6. spec 品質自檢（全過才進 backlog）
- [ ] 驗收條件可測試（指令/validator/截圖判準寫得出來）
- [ ] non-goals 寫了（本專案常見：不改重播輸入、不動 SINR 真值、不升 Jain 為 win 軸）
- [ ] 邊界情況列了（空資料、載入中、degraded 狀態）
- [ ] **是否觸及金流/個資/醫療等高風險**——觸及則此目標強制加真人專家審查關卡（本專案整體為否，仍逐目標檢查）
- [ ] 前端工作 → 已對照 frontend-change-contract 判定 lane 歸屬與 gate 影響面

## 產出（一次落檔）

1. `docs/devkit/intent.md` 新條目：why、non-goals、驗收條件、建議預算等級（S/M/L/XL）、前置/blocker。優先序欄留給使用者。
2. 假設帳新增項。
3. 閘門降維三件套（使用者無法評估方案時必附）：「什麼情況下這個選擇會被證明是錯的」「逃生路線與成本」「更無聊但更可逆的替代案」。決策啟發式：可逆優先、無聊技術優先。
4. 回報使用者：復述定稿＋條目位置＋下一步（「說『跑 pipeline』開工」）。

## 偏好學習

每輪 A/B 回答 append `.claude/devkit-local/decision-log.md`。詢問次數應隨側寫變準而下降——不是因為橡皮圖章，是因為預測變準。連續三次某類問題使用者都選同一方向 → 提案寫進偏好側寫（維護迴圈編譯）。
